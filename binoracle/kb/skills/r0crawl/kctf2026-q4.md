# Summary of the Challenge

## Supplementary Verifiable Constants

- Target username: `KCTF`; valid Serial length is 9226 bytes.
- Serial format: `lI|0O` + 9216-byte body + `Il1|!`.
- Body alphabet: `Il1|!ijJL\`oO0QDSs5$Zz2B8gq96nNmMWwUuVvRrPpCc({tT+7xXKkYyAa4Ee3FH`.
- Inverse custom Base64: `v=(alphabet_index[ch]+51+27*i)&63`, standard Base64 decodes 6912 bytes.
- Public solution provides the final Serial SHA-256 hash: `e34dc3a75754abf44a96d4902bac38b5dd0310fffb2974b27cc84b932ae5847b`.
- Plaintext decimal record length is approximately 6897 bytes, padded to 6912 with NULs; 100 groups of ten polynomial expressions contain 1000 integer roots.

The goal is to construct a valid Serial for the given username `KCTF`. The program is 32-bit PE but contains core algorithms in 64-bit code. It simulates an instruction set through exception handling and selects true or false algorithms based on parent process/PEB states.

## Standard Solution Workflow

1. **Confirm Real Execution Environment**
   - Entry point `sub_4010E0` saves registers then executes `push 0x33; retf` (Heaven's Gate) to switch into long mode.
   - Privileged instructions like `in`, `out`, and `int3` are not I/O but custom VM commands captured by VEH (`Warning`). For example, opcode `0xED` triggers a debugger warning, `0xEE` checks length, `0xEF` derives keys, and `0xEC` computes obfuscated jumps.
   - The program enumerates parent processes and hashes their names using djb2; only explorer/cmd/powershell are allowed to enter the true algorithm. PEB's `BeingDebugged` byte is incremented by `0x1A` and `0x40` in AES and format validation phases, resulting in a combined key of `0x5A`. Any debug or patching step will lead to false paths.

2. **Recover Custom Encoding (Outer Serial)**
   - The valid Serial has fixed length of 9226 bytes: 5 characters at each end + 9216-byte body; the character set consists of 64 printable ASCII characters.
   - For each position `i` in the body, the index `a_i` and actual 6-bit value `v_i`: `v_i=(a_i+51+27*i) mod 64`; decoding reverses to get `a_i=(v_i-51-27*i) mod 64`. The ciphertext of 6912 bytes corresponds to 432 16-byte blocks.

3. **Reverse the Modified AES Layer**
   - Confirm ECB (only changes in output for same block) through input differences. State is stored column-wise, and rounds are computed row-wise; use inverse column mixing and rightward row transformations instead of standard AES library.
   - In an exception context, poll threads on `CONTEXT`/XMM registers to sample adjacent round states without pausing or writing memory; differential recovery of GF(2^8) S-boxes, round keys, and first XOR value under polynomial `0x11B`.
   - After each linear layer, XOR with a constant `0x40` must be preserved in the reimplementation.

4. **Solve Polynomial Roots to Construct Plaintext**
   - The username is hashed 31 times using Murmur's `fmix`, then cyclically taking `state & 0x3fff` and removing duplicates yields 100 rows.
   - Each row contains 11 compressed BCD coefficients, decryption key: `base=(group*0x9E3779B9) XOR (coef_index*0x517CC1B7)`. After decoding, the first byte indicates a sign and seven decimal digits; subsequent half-bytes are decimal coefficients.
   - For each group of 10 polynomial expressions, integer roots correspond to 10 distinct integers. Standard groups factorize within integer ranges using Horner's method for verification; Group 84 deliberately alters the leading coefficient, enumerates constant term factors, and sequentially substitutes to find 10 unique integer roots.
   - Roots are sorted by group in ascending order, concatenated with `-` to form 1000 decimal numbers. Note length constraints: prepend six `0`s before the first integer, total length of 6897 bytes; then pad NULs to reach 6912 bytes.

5. **Validate and Deliver**
   - Encrypt 6912 bytes using custom AES in forward mode, encode with position-related Base64, and add fixed headers/tails to form the Serial.
   - Initially test single-character differences to confirm each block's path; finally validate `Successful!` under original unpatched program, whitelisted parent process, no debugger.
