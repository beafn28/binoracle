Tutorial de binoracle

Este tutorial recorre todas las capacidades de binoracle: desde la instalación inicial hasta ejecutar una investigación CVE completa y generar una cadena de exploit contra un binario local. Todo se ejecuta en tu máquina; no se requieren claves de API externas ni servicios en la nube.

Aviso legal — binoracle es una herramienta de investigación y educación. Todos los laboratorios CVE se ejecutan contra contenedores Docker que tú creas localmente. No la uses contra sistemas que no sean tuyos o para los que no tengas permiso escrito explícito.

1. Instalación

binoracle requiere Python 3.10 o superior y Docker 20+. Instala con pip:

pip install binoracle

Instala extras opcionales para desbloquear backends de análisis adicionales:

pip install binoracle[pwn]        # pwntools + ROPgadget
pip install binoracle[symbolic]   # ejecución simbólica angr
pip install binoracle[screenshots] # capturas Playwright en informes CVE
pip install binoracle[all]        # todo lo anterior

Verifica la instalación:

binoracle --version

2. Configuración

binoracle necesita un LLM local para generar hipótesis de exploit. La configuración recomendada es Qwen 2.5 Coder 7B ejecutándose mediante Ollama.

Instalar Ollama y descargar el modelo

# Linux / macOS
curl -fsSL https://ollama.com/install.sh | sh
ollama pull qwen2.5-coder:7b

Variables de entorno

export BINORACLE_BACKEND=openai
export BINORACLE_BASE_URL=http://127.0.0.1:11434/v1
export BINORACLE_MODEL=qwen2.5-coder:7b
export BINORACLE_LANG=es    # idioma del informe: es o en

Añade estas líneas a tu perfil de shell (~/.bashrc, ~/.zshrc) para que persistan entre sesiones.

3. Motor CVE

El motor CVE toma un identificador CVE, recupera el descriptor de NVD, lo envía al LLM local, y genera y verifica de forma autónoma un proof-of-concept de exploit contra un laboratorio Docker efímero.

Uso básico

# Investigar un CVE individual
binoracle cve CVE-2025-27516

# Lote, paralelizado
binoracle cve-batch CVE-2025-27516 CVE-2024-23334 CVE-2025-59681

# Informe en inglés
binoracle cve CVE-2025-27516 --lang en

# Guardar en directorio específico
binoracle cve CVE-2025-27516 --out ./informes/

# Abrir el informe al terminar
binoracle cve CVE-2025-27516 --open-report

Pasos del motor, en detalle

PasoQué ocurre
1 — Obtención NVDRecupera el registro CVE: identificador, puntuación CVSS, versión del paquete afectado y la descripción en lenguaje natural.
2 — Hipótesis LLMQwen 2.5 Coder lee la descripción y genera una hipótesis estructurada: clase de vulnerabilidad (SSTI, SQLi, RCE…), endpoint afectado, estrategia de payload y scaffolder tecnológico.
3 — Selección del scaffolderEl motor mapea el ecosistema detectado (Flask, Rails, Spring, WordPress…) a la plantilla Docker Compose correspondiente.
4 — Laboratorio DockerSe construye y arranca un lab efímero con el paquete vulnerable fijado en la versión afectada. El lab se destruye al finalizar la ejecución.
5 — Verificación PlaywrightEl PoC se ejecuta contra el lab. Playwright captura pantallas en cada paso HTTP, registra los pares solicitud/respuesta y escribe el informe HTML estructurado.

4. Motor de Reversing Binario

El motor binario proporciona generación de exploits automatizada, análisis estático, decompilación y síntesis de cadenas ROP para una amplia variedad de formatos binarios.

Uso básico

# Cadena de exploit completa — técnica seleccionada automáticamente
binoracle pwn ./binario

# Análisis estático: mitigaciones, símbolos, importaciones, secciones
binoracle triage ./binario

# Decompilación multi-motor
binoracle decompile ./binario

# Búsqueda de gadgets ROP y síntesis de cadena
binoracle rop ./binario

# Evaluación de hardening con notas de bypass
binoracle hardening ./binario

5. Servidor MCP

Inicia el servidor MCP para exponer todas las capacidades de binoracle como ~100 herramientas a clientes compatibles con MCP como Claude Desktop, Cursor o Zed.

binoracle mcp-server
// claude_desktop_config.json
{
  "mcpServers": {
    "binoracle": {
      "command": "binoracle",
      "args": ["mcp-server"]
    }
  }
}

6. Informes

Cada investigación CVE genera un informe HTML con:

  • Resumen ejecutivo con puntuación CVSS y clasificación de severidad
  • Hipótesis del LLM con la cadena de razonamiento completa
  • Configuración del laboratorio y especificación Docker Compose
  • Capturas de pantalla de Playwright en cada paso de verificación
  • Código PoC completo (curl, Python, pwntools)
  • Recomendaciones de remediación con orientación específica

7. Corpus de práctica

binoracle incluye más de 40 binarios intencionalmente vulnerables para práctica local. Compílalos con Docker o gcc nativo:

samples/build.sh

Técnicas cubiertas: ret2win, ret2libc, SROP, tcache dup, fastbin dup, UAF, format string GOT overwrite, canary leak, PIE leak, CSU chain, DL-resolve, heap botcake, house-of-orange, unsafe-unlink, stack pivot, IO_FILE, callhijack, dlresolve32.
