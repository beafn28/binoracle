Web UI

binoracle ships a browser-based interface that covers both pillars: CVE exploit development and binary reversing. All output streams live via SSE — no page reloads, no polling. Everything runs locally on port 8000; no data leaves your machine.

Start the UI

Launch the web server from any terminal:

binoracle web

Open http://localhost:8000 in your browser. The terminal prints bin0racle Exploit Dev → http://localhost:8000 when ready. All tabs and tools are immediately available; no login or API key is required beyond your local LLM configuration.

Tip: Run binoracle doctor in the System tab first to verify your environment (Ghidra, radare2, Python deps) before starting a session.

Dev Exploit tab

The main run panel at the top of the page drives CVE exploit research. Select a mode and enter a CVE ID or description, then click Run.

ModeCLI commandWhat it does
Dev Exploitbinoracle cve <CVE-ID>Full autonomous exploit research: NVD lookup → LLM hypothesis → source download → code analysis → PoC generation → verification
Exploit Planbinoracle cveplan <query>Generate an exploitation plan for a CVE ID or plain-text vulnerability description without running a full exploit attempt

Output streams to the Live Log tab in real time. When a run completes, switch to Report for the structured markdown writeup, Evidence for extracted artefacts, HTTP Requests for captured traffic, and Screenshots if the run captured browser evidence. The Export PDF button activates once a report is ready.

Exploit Plan tab

Use this tab to generate an exploitation plan interactively, without uploading a binary or running a full CVE pipeline. Type a CVE ID or describe the vulnerability in plain text and press Plan.

# Examples
CVE-2024-1071
SQL injection in WordPress plugin via unauthenticated REST endpoint

Note: For binary-specific questions (e.g. "what gadgets are available in this ELF?"), upload the file in Binary Lab and use the ask command there instead.

Binary Lab tab

Upload any supported binary (ELF, PE, Mach-O, APK, firmware, WASM, …) and run the full reversing toolkit. After upload a file ID is assigned and all subsequent commands target that file until you upload another.

Architecture note

The web server (binoracle web) spawns python -m binoracle <cmd> [args] as a subprocess for every run. Output is streamed back to the browser over Server-Sent Events (SSE) — a persistent HTTP connection where the server pushes newline-delimited data: frames. Each job gets a job_id; the browser subscribes to /api/stream/<job_id> and renders lines as they arrive.

No WebSocket, no polling. The binary upload endpoint (/api/binary/upload) stores the file under a session-scoped file_id that subsequent commands reference. Commands that need no binary (ask, cveplan, cyclic, shellcode, …) use the reserved __nofile__ identifier.
