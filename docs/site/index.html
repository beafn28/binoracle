GitHub Roadmap

Two independent analysis pipelines

binoracle combines a CVE exploit research engine with a binary reverse engineering engine, both running fully offline on your machine.

CVE Engine

Retrieves a CVE descriptor from NVD and submits it to a local LLM which autonomously generates exploit hypotheses without external hints. Provisions an ephemeral Docker Compose lab, executes the proof-of-concept, captures Playwright screenshots, and emits a structured HTML report.

NVDQwen 2.5 Coder 7BDockerPlaywright

Binary RE Engine

Static and dynamic analysis of ELF, PE, Mach-O, APK, WASM, Go, Rust, .NET, JS, EVM, and SQLite artifacts. Covers exploit generation across stack, heap, format string, and SROP primitives, plus ROP chain synthesis and multi-backend decompilation. All operations are local.

50+ exploit familiespwntoolsradare2angr

MCP Server

Exposes binoracle's full capability set as ~100 MCP tools, enabling integration with Claude Desktop, Cursor, Zed, and other MCP-compatible clients. Start the server with one command and add it to your client's configuration.

How the CVE engine works

The engine is fully autonomous — the local LLM receives only the NVD description and no analyst-supplied hints. All exploit hypotheses are derived from that description alone.

Step 1

NVD Fetch

Retrieves the CVE record from the NVD API: identifier, CVSS score, affected package, and the plain-language description.

Step 2

LLM Hypothesis

Qwen 2.5 Coder 7B reads the description and generates a structured hypothesis: vulnerability class, affected endpoint, payload strategy, and ecosystem scaffolder.

Step 3

Hypothesis Validation

The engine parses the hypothesis output and selects the matching lab scaffolder based on the detected technology stack.

Step 4

Docker Lab

An ephemeral Docker Compose lab is provisioned with the vulnerable package at the specified version. The lab tears down automatically after the run.

Step 5

Playwright Verify

The PoC is executed against the running lab. Playwright captures screenshots at each HTTP step, records the response, and writes the HTML report.

Zero cloud calls

No data leaves your machine at any point. The LLM runs locally via Ollama, Docker labs are ephemeral and local, and reports are written to disk.

  • LLM via Ollama at localhost:11434
  • Docker labs torn down after each run
  • Reports written to disk only
  • No telemetry, no account required

Quick start

Three steps from zero to running your first CVE investigation.

terminal 
# 1. Install binoracle
pip install binoracle

# 2. Install Ollama and pull the model (Linux / macOS)
curl -fsSL https://ollama.com/install.sh | sh
ollama pull qwen2.5-coder:7b

# 3. Configure the LLM backend
export BINORACLE_BACKEND=openai
export BINORACLE_BASE_URL=http://127.0.0.1:11434/v1
export BINORACLE_MODEL=qwen2.5-coder:7b

# Run the CVE engine
binoracle cve CVE-2025-27516

# Analyze a binary
binoracle triage ./target_binary
binoracle pwn ./vulnerable_binary

Architecture

binoracle is composed of an interface layer (CLI, MCP server, web UI), a workflow layer that orchestrates the analysis, and three backend layers: the Oracle (deterministic analysis), the LLM Bridge (local Qwen via Ollama), and the Lab Scaffolder (ephemeral Docker labs).
