binoracle

Autonomous CVE exploit research and binary reverse engineering — 100% local, zero cloud calls.

Legal notice — binoracle is a research and educational tool. All CVE labs run exclusively against Docker containers you provision locally. Do not use this tool against systems you do not own or lack explicit written authorization to test.

Quick start

# Install
pip install binoracle

# Install Ollama and pull the model (Linux / macOS)
curl -fsSL https://ollama.com/install.sh | sh
ollama pull qwen2.5-coder:7b

# Configure the LLM backend
export BINORACLE_BACKEND=openai
export BINORACLE_BASE_URL=http://127.0.0.1:11434/v1
export BINORACLE_MODEL=qwen2.5-coder:7b

# Run the CVE engine autonomously
binoracle cve CVE-2025-27516

# Static analysis on a binary
binoracle triage ./target_binary

# Full exploit chain
binoracle pwn ./vulnerable_binary

Engines

EngineDescription
CVE Engine Retrieves a CVE descriptor from NVD, feeds it to a local LLM (Qwen 2.5 Coder 7B via Ollama) which autonomously generates exploit hypotheses — no external hints supplied. Provisions an ephemeral Docker Compose lab, executes the proof-of-concept, captures Playwright screenshots at each step, and emits a structured HTML report.
Binary RE Engine Static and dynamic analysis of ELF, PE, Mach-O, APK, WASM, Go, Rust, .NET, JS, EVM and SQLite. Covers exploit generation (stack, heap, format string, SROP), ROP chain synthesis, multi-backend decompilation, and hardening assessment. All operations run locally.
MCP Server Exposes the full capability set as ~100 MCP tools, enabling integration with Claude Desktop, Cursor, Zed, and other MCP-compatible clients.

CVE Engine

The engine is fully autonomous — the local LLM receives only the NVD description and no analyst-supplied hints. All exploit hypotheses are generated from that description alone.

Commands

# Single CVE
binoracle cve CVE-2025-27516

# Batch, parallelized
binoracle cve-batch CVE-2025-27516 CVE-2024-23334 CVE-2025-59681

# Report language override
binoracle cve CVE-2025-27516 --lang en

Binary RE Engine

50+ exploit families automated end-to-end. Static analysis, dynamic tracing, decompilation, and exploit chain generation across multiple binary formats.

Commands

binoracle triage ./binary        # mitigations, symbols, imports, sections
binoracle decompile ./binary     # multi-backend: Ghidra, radare2, angr, pwndbg
binoracle rop ./binary           # ROP gadget search + chain synthesis
binoracle chain ./binary         # full exploit chain generation
binoracle hardening ./binary     # NX, PIE, RELRO, canary, Fortify, CFI

MCP Server

binoracle exposes its full capability set as MCP tools, enabling integration with Claude Desktop, Cursor, Zed, and other MCP-compatible clients.

binoracle mcp-server
// claude_desktop_config.json
{
  "mcpServers": {
    "binoracle": {
      "command": "binoracle",
      "args": ["mcp-server"]
    }
  }
}

Installation

pip install binoracle

Optional dependency sets:

pip install binoracle[pwn]        # pwntools + ROPgadget
pip install binoracle[symbolic]   # angr symbolic execution
pip install binoracle[screenshots] # Playwright screenshots in CVE reports
pip install binoracle[all]        # all of the above

Configuration

# Local LLM via Ollama (recommended)
export BINORACLE_BACKEND=openai
export BINORACLE_BASE_URL=http://127.0.0.1:11434/v1
export BINORACLE_MODEL=qwen2.5-coder:7b

# Report language (default: es)
export BINORACLE_LANG=en

Add these to your shell profile (~/.bashrc, ~/.zshrc) to persist them across sessions.
