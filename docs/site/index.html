Quick Start

Prerequisites: Python 3.10+, Docker 20.x+, Ollama 0.3+.

# 1. Install binoracle
pip install binoracle

# 2. Install Ollama and pull the model (Linux / macOS)
curl -fsSL https://ollama.com/install.sh | sh
ollama pull qwen2.5-coder:7b

# 3. Configure the LLM backend
export BINORACLE_BACKEND=openai
export BINORACLE_BASE_URL=http://127.0.0.1:11434/v1
export BINORACLE_MODEL=qwen2.5-coder:7b

# 4. Run the CVE engine on a real CVE
binoracle cve CVE-2025-27516

# 5. Analyse a binary
binoracle triage ./target_binary
Persist configuration. Add the three export lines to ~/.bashrc or ~/.zshrc so they survive shell restarts.

Two Pipelines

binoracle exposes two independent analysis pipelines that can be used separately or combined.

CVE Pipeline

Takes a CVE identifier. Retrieves the NVD descriptor, passes it to a local LLM which generates exploit hypotheses autonomously. Provisions an ephemeral Docker Compose lab, executes the proof-of-concept, records Playwright screenshots at every verification step, and emits a self-contained HTML report to disk.

No data is sent to external services. The LLM runs entirely on your machine via Ollama.

binoracle cve CVE-2025-27516
binoracle cve-batch CVE-2025-27516 CVE-2024-23334

Binary RE Pipeline

Takes a binary file. Runs static analysis (symbols, imports, sections, mitigations), optionally dynamic tracing, feeds the decompiled output to the LLM which selects an exploit technique and generates a working pwntools script. Outputs a structured HTML report with the full reasoning chain.

Supports ELF, PE, Mach-O, APK, WASM, Go, Rust, .NET, EVM, and SQLite formats.

binoracle triage ./binary
binoracle pwn    ./binary

CVE Engine

The CVE engine is fully autonomous. The local LLM receives only the raw NVD description — no analyst-supplied hints, no guided prompts, no pre-filled templates. Hypotheses are generated entirely from that description.

 NVD / NIST          LLM local           Docker lab         Playwright          HTML report
 CVE descriptor  -->  Qwen 2.5 Coder  -->  ephemeral env  -->  screenshots    -->  disk only
                      zero hints           Docker Compose      each step           HTML+CSS

Each CVE run provisions a fresh Docker Compose environment scoped to that CVE. The environment is torn down automatically after the run. No persistent lab state is kept between runs.

Binary RE Engine

Static and dynamic analysis pipeline for binary files. Covers 50+ exploit families across stack, heap, format string, and low-level categories. All analysis runs locally without uploading the binary.

 Binary input
     |
     +-- Static analysis -- symbols, imports, sections, mitigations (NX/PIE/RELRO/canary)
     |
     +-- LLM analysis ----- decompiled code review, vuln patterns, technique selection
     |
     +-- Dynamic (opt) ---- strace / ltrace / gdb automation
     |
     +-- Exploit gen ------ pwntools script + structured HTML report

Commands

binoracle triage ./binary        # mitigations, symbols, imports, sections
binoracle decompile ./binary     # multi-backend: Ghidra, radare2, angr, pwndbg + LLM
binoracle pwn ./binary           # full exploit chain, technique auto-selected
binoracle rop ./binary           # ROP gadget search + chain synthesis
binoracle chain ./binary         # gadget enumeration + pwntools script
binoracle heap ./binary          # heap exploit primitives
binoracle fmt ./binary           # format string exploitation
binoracle srop ./binary          # SROP chain generation
binoracle shellcode ./binary     # shellcode with bad-char filtering
binoracle hardening ./binary     # NX, PIE, RELRO, canary, Fortify, CFI audit

Reports

Every CVE investigation and binary analysis writes a self-contained HTML report to disk. Reports are single-file HTML with embedded CSS — no external dependencies required to view them.

SectionContents
Executive summaryCVSS score, severity rating, affected component and version
HypothesisFull LLM reasoning chain showing how the exploit was derived
LabDocker Compose specification, service versions, network configuration
EvidencePlaywright screenshots captured at each verification step
PoCComplete, runnable curl / Python / pwntools exploit code
RemediationSpecific fix guidance with before/after code examples
 
# Open report immediately after run
binoracle cve CVE-2025-27516 --open-report

# Write to a specific directory
binoracle cve CVE-2025-27516 --out ./reports/

# Batch with output directory
binoracle cve-batch CVE-2025-27516 CVE-2024-23334 --out ./reports/

MCP Integration

binoracle exposes its full toolkit as an MCP server, making all analysis capabilities available to any MCP-compatible client: Claude Desktop, Cursor, Zed, and others. The server runs locally and does not require network access.

binoracle mcp-server

Add to your client configuration:

{
  "mcpServers": {
    "binoracle": {
      "command": "binoracle",
      "args": ["mcp-server"]
    }
  }
}

Configuration

All configuration is via environment variables. No configuration file is required.

VariableDefaultDescription
BINORACLE_BACKENDopenaiLLM backend protocol (openai-compatible)
BINORACLE_BASE_URLnoneLLM API base URL (e.g. http://127.0.0.1:11434/v1)
BINORACLE_MODELnoneModel identifier (e.g. qwen2.5-coder:7b)
BINORACLE_API_KEYnoneAPI key — only needed for cloud backends
BINORACLE_LANGesReport language: es or en
 
# Local Ollama (recommended — fully offline)
export BINORACLE_BACKEND=openai
export BINORACLE_BASE_URL=http://127.0.0.1:11434/v1
export BINORACLE_MODEL=qwen2.5-coder:7b

# OpenAI-compatible cloud backend (optional)
export BINORACLE_BASE_URL=https://api.openai.com/v1
export BINORACLE_API_KEY=sk-...
export BINORACLE_MODEL=gpt-4o-mini

# English reports
export BINORACLE_LANG=en

Practice Corpus

The repository includes 40+ intentionally vulnerable binaries for local exploitation practice. Each binary is built with a specific vulnerability and mitigations set to exercise a particular technique.

# Build all samples (requires Docker or gcc)
samples/build.sh

# Run the exploit chain against a sample
binoracle pwn samples/bin/ret2libc
binoracle pwn samples/bin/tcache_dup
binoracle pwn samples/bin/house_of_orange
binoracle pwn samples/bin/format_string
binoracle pwn samples/bin/srop_x64

Techniques covered: ret2win, ret2libc, SROP, tcache dup, fastbin dup, UAF, format string GOT overwrite, canary leak, PIE leak, CSU chain, DL-resolve, heap botcake, house-of-orange, unsafe-unlink, stack pivot, IO_FILE, callhijack, dlresolve32.
