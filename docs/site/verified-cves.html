Manual steps

All WordPress CVEs below were verified autonomously: the engine downloaded the vulnerable plugin from WordPress.org, spun up an ephemeral Docker lab (WordPress + MySQL), ran a source-code analysis pass with the local LLM, generated and fired payloads, and confirmed the vulnerability by extracting a real MySQL version() value or observing a time-delayed response. No manual payload crafting. No existing PoC lookup.

Methodology

WordPress Lab Pipeline

Each WordPress CVE verification runs through these stages automatically:

  1. Download vulnerable plugin version from WordPress.org into a local cache
  2. Spin up an ephemeral Docker lab: WordPress (PHP/Apache) + MySQL, exposed on a random port
  3. Run LLM-assisted source analysis on the plugin code (concurrent with lab spin-up)
  4. Apply setup fixtures: install plugin, create admin/subscriber users, configure WP options
  5. Fire probes: error-based, UNION-based, boolean-blind, time-based blind, ORDER BY context
  6. On negative: LLM-guided retry loop — reads real HTTP evidence, suggests endpoint/param changes
  7. Confirm: either version() extracted in response (UNION/error) or ≥3.5 s delay measured (time-based)
  8. Teardown: containers and anonymous MySQL volumes pruned automatically

LLM Stack

All analysis runs locally via Qwen2.5-Coder:7b (Ollama). No data is sent to external AI services. The LLM performs source triage, endpoint discovery, parameter locking, and retry guidance — not payload generation (that is rule-based in the verifier).

Verification Criteria

A CVE is marked VERIFICADO only when the engine observes one of:

  • The real MySQL/PostgreSQL version string appears inside the HTTP response body (UNION-based or error-based proof)
  • ≥3 out of N timing pairs show ≥3.5 s delay for SLEEP(5) vs. SLEEP(0) control (time-based blind proof)

Both conditions use data extracted from actual HTTP responses against a real running database — not static analysis inference or PoC replay.

Run this yourself

# Verify a WordPress plugin CVE autonomously
binoracle cve CVE-2024-9634 \
  --source give \
  --vuln-class sqli \
  --endpoint /wp-json/give-api/v2/form-grid \
  --params orderby

# LearnPress CVE with nested WP option setup
binoracle cve CVE-2024-4434 \
  --source learnpress \
  --vuln-class sqli \
  --endpoint /wp-json/lp/v1/courses/archive-course \
  --params term_id \
  --setup-wp-option "learnpress[get_courses_of_subcategory]=yes"
