Firmware Analysis

binoracle can analyse firmware images from IoT devices, routers, embedded systems and industrial controllers. It extracts the filesystem, identifies binaries with known vulnerability classes, and applies the full radare2 + LLM analysis pipeline to each one.

Firmware Layers

A typical firmware image packages several layers: a bootloader, a compressed kernel, and a compressed root filesystem. binoracle works at the filesystem layer — it extracts the SquashFS/JFFS2/CRAMFS image and analyses the ELF binaries inside it.

Extraction

binoracle firmware <image.bin> [options]

Options:
  --extract-to DIR         Write extracted files to DIR (default: ./firmware_out/)
  --list                   List all ELF binaries found, don't analyse
  --focus GLOB             Only analyse binaries matching this glob (e.g. '*/httpd')
  --depth N                Max directory depth to recurse (default: unlimited)
  -o FILE                  HTML report output path
  --json FILE              Dump findings as JSON

Extraction is handled by a chain of format detectors:

  1. File signature detection — identifies SquashFS, JFFS2, CRAMFS, gzip, lzma, bzip2, 7z, cpio, tar, zip by magic bytes.
  2. Binwalk-style carving (built-in, no binwalk dependency) — scans for embedded archives at any offset within the image.
  3. Recursive extraction — decompresses each layer. For SquashFS it calls unsquashfs (must be installed); for other formats it uses Python's stdlib (tarfile, zipfile, gzip, lzma).
  4. ELF enumeration — walks the extracted tree and collects every file with ELF magic bytes, regardless of extension.
Requirement: unsquashfs must be installed to extract SquashFS images (apt install squashfs-tools / brew install squashfs). For other formats only Python stdlib is needed.

Binary Analysis

Each extracted ELF is run through the full binoracle RE pipeline:

  1. Triage — checksec, architecture detection (ARM32, ARM64, MIPS, x86, x64, PowerPC), libc version estimation from embedded strings.
  2. Hunt — static vulnerability hunting: format strings, dangerous function calls (strcpy, gets, system, popen), hardcoded credentials in .rodata, world-writable sockets.
  3. LLM analysis — context-aware analysis of decompiled output for the highest-risk functions identified in the hunt step.
  4. Auto-verify (optional, x86/x64 only) — angr symbolic execution to prove reachability and compute overflow offsets.
# Analyse a TP-Link firmware image, focus on the httpd binary
binoracle firmware tplink_archer_c7.bin --focus '*/httpd' -o firmware-report.html

# List all ELF binaries in a firmware image without analysing
binoracle firmware openwrt-snapshot.bin --list

# Full analysis, all binaries, write JSON
binoracle firmware netgear-r7000.bin --json firmware.json -o firmware.html

Mitigations in Embedded Systems

Embedded firmware often lacks modern exploit mitigations. binoracle's triage step reports:

MitigationWhat it meansTypical embedded status
NX / DEPNon-executable stack/heapOften absent on MIPS/ARM32 without hardware support
Stack canaryDetects stack overflows before returnAbsent in ~60% of embedded binaries (stripped builds)
PIE / ASLRRandomised base addressOften absent; fixed addresses make ROP chains reliable
RELRORead-only GOT after relocationPartial RELRO common; Full RELRO rare
FORTIFY_SOURCERuntime bounds checks on libc callsRarely present in stripped builds

When mitigations are absent, binoracle notes this explicitly in the report and adjusts the exploitability assessment — a stack overflow in a binary with no NX, no canary and no ASLR is rated as trivially exploitable.

Use Cases

Router hardcoded credentials

Many routers embed hardcoded SSH/Telnet/web credentials in .rodata. binoracle's hunt step searches for strings matching admin, password, root, 1234 adjacent to auth-related function calls and flags them as findings.

MIPS/ARM buffer overflows in httpd

The most common vulnerability class in embedded web servers is an unchecked strcpy from a URL or CGI parameter into a stack buffer. binoracle identifies these statically and, for x86/x64 test builds, can symbolically verify them with angr.

Industrial controller (ICS/SCADA) firmware

Many ICS controllers run Linux on ARM with stripped binaries and no ASLR. binoracle can analyse their management daemons, Modbus/DNP3 stacks, and OPC-UA servers for memory corruption and injection flaws.
