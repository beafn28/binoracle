Architecture

Three clearly separated planes: static readers, analysis/arsenal, and execution-verified exploit engine. A CVE layer on top. Three interfaces at the bottom.

Three Planes

Plane 1 — Static Readers

Identify the format and extract facts. Never execute the target.

elf_reader pe_reader macho_reader apk_reader flutter_reader dotnet_reader js_reader wasm_reader sqlite_reader evm_reader secrets_scanner
↓
Plane 2 — Analysis / Arsenal

Reason over static facts. Build ROP chains, identify primitives, map attack surface.

chain_analyzer rop_arsenal gadget_finder primitive_detector surface_mapper nativequery nativesession rag_kb
↓
Plane 3 — Exploit Engine (execution-verified)

Build and confirm exploits. Runs in an isolated sandbox. Only marks VERIFIED with real shell.

autopwn autopoc autoheap autoheap_shell autopie_rop verify_chain run_driver sandbox (docker|native)

CVE Engine Layer

CVE pipeline (wraps all three planes)
nvd_fetcher cve_agent (Qwen 2.5) lab scaffolds exploit_runner report_generator playwright_screenshots

Interfaces

CLI

50+ subcommands. Everything accessible from the terminal. binoracle <cmd> --help for each.

binoracle investigate …
binoracle autopwn …
binoracle elf …
binoracle serve

MCP Server

~100 tools over JSON-RPC stdio. Connect to Claude Desktop, VS Code, or any MCP client.

binoracle mcp

Web UI

Local web interface at http://127.0.0.1:8080. API at POST /api/run.

binoracle serve

Sandbox

Docker sandbox

Preferred. Uses binoracle-pwn Docker image (Python + pwntools + one_gadget). Deterministic, portable.

build once
make pwn-image

Native sandbox

Fallback on Linux x86-64 when Docker is absent. User + network namespace (unshare -rn), ASLR off (setarch -R), resource limits (CPU/memory/pids).

Result records which engine verified: docker or native.
