MCP Tools Reference

binoracle exposes every capability as an MCP (Model Context Protocol) tool. Connect Claude Desktop, VS Code with Continue, Zed, or any MCP-compatible client to run binoracle's full exploit research pipeline from within your AI assistant.

Setup

Start the MCP server:

binoracle mcp-server

The server communicates over stdio and implements the MCP specification. No network port is opened — the client process spawns binoracle as a subprocess and communicates via stdin/stdout pipes.

Claude Desktop

Add binoracle to ~/.claude/claude_desktop_config.json:

{
  "mcpServers": {
    "binoracle": {
      "command": "binoracle",
      "args": ["mcp-server"],
      "env": {
        "BINORACLE_BACKEND": "ollama",
        "BINORACLE_MODEL": "qwen2.5-coder:7b"
      }
    }
  }
}

Restart Claude Desktop. You will see binoracle's tools appear in the tool picker. You can now ask Claude things like:

  • "Investigate CVE-2024-1071 and give me the HTML report"
  • "Triage the binary at /path/to/binary and find vulnerabilities"
  • "Decompile the main function of /tmp/challenge"
  • "Analyse this firmware image: /tmp/router.bin"

VS Code (Continue)

Add to ~/.continue/config.json:

{
  "mcpServers": [
    {
      "name": "binoracle",
      "command": "binoracle",
      "args": ["mcp-server"]
    }
  ]
}

After adding it, Continue will auto-discover all binoracle tools. Use @binoracle in the Continue chat to scope tool calls.

Examples

Ask Claude to investigate a CVE

In Claude Desktop, with binoracle connected:

User: Investigate CVE-2024-27956 and tell me if it's exploitable.
       Save the report to /tmp/report.html

Claude: [calls investigate_cve(cve_id="CVE-2024-27956")]
        [calls render_report(markdown=..., cve="CVE-2024-27956")]
        The CVE is confirmed exploitable. CVSS 9.8 CRITICAL.
        Class: sqli (authentication bypass). Affected: WP Automatic <= 3.92.0.
        Report saved to /tmp/report.html.

Binary analysis in Claude Desktop

User: There's a binary at /tmp/challenge. Find vulnerabilities and
       give me an exploit strategy.

Claude: [calls triage_binary(binary_path="/tmp/challenge")]
        [calls hunt_binary(binary_path="/tmp/challenge")]
        [calls decompile_function(binary_path="/tmp/challenge", function="main")]
        [calls autopwn(binary_path="/tmp/challenge")]

        I found a stack-based buffer overflow in main() at offset 0x104.
        No canary, no PIE, NX enabled.
        Strategy: ret2plt → leak libc → ret2libc for shell.
        Here's the pwntools script: ...

Firmware analysis via MCP

User: Analyse this IoT firmware: /tmp/firmware.bin
       Focus on network-facing daemons.

Claude: [calls analyse_firmware(image_path="/tmp/firmware.bin", focus="*/httpd")]
        Found 3 binaries: httpd, utelnetd, miniupnpd
        httpd (MIPS32, no NX, no canary):
          - strcpy overflow in CGI parameter handler (HIGH)
          - hardcoded admin:admin credential in .rodata (HIGH)
        utelnetd: telnet enabled with no auth (CRITICAL)
        miniupnpd: format string in AddPortMapping handler (HIGH)
Note: All file paths in MCP tool calls must be absolute paths accessible to the binoracle server process. If binoracle is running in a container or VM, paths must be accessible inside that environment.
