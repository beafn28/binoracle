binoracle Tutorial

This tutorial walks through every capability binoracle provides — from initial setup to running a full CVE investigation and generating an exploit chain against a local binary. All operations run entirely on your machine; no external API keys or cloud services are required.

Legal notice — binoracle is a research and educational tool. All CVE labs run against Docker containers you provision locally. Do not use this tool against systems you do not own or lack explicit written authorization to test.

1. Installation

pip install binoracle
pip install binoracle[pwn]        # pwntools + ROPgadget
pip install binoracle[symbolic]   # angr symbolic execution
pip install binoracle[screenshots] # Playwright screenshots
pip install binoracle[all]        # all of the above

Verify: binoracle --version

2. Configuration

# Linux / macOS
curl -fsSL https://ollama.com/install.sh | sh
ollama pull qwen2.5-coder:7b

export BINORACLE_BACKEND=openai

export BINORACLE_MODEL=qwen2.5-coder:7b
export BINORACLE_LANG=en

3. CVE Engine

The CVE engine takes a CVE identifier, retrieves the descriptor from NVD, feeds it to the local LLM, and autonomously generates and verifies an exploit proof-of-concept against an ephemeral Docker lab.

binoracle cve CVE-2025-27516
binoracle cve-batch CVE-2025-27516 CVE-2024-23334
binoracle cve CVE-2025-27516 --lang en
binoracle cve CVE-2025-27516 --out ./reports/
binoracle cve CVE-2025-27516 --open-report

What the engine does, step by step

StepWhat happens
1 — NVD fetchRetrieves CVE identifier, CVSS score, affected version, and plain-language description.
2 — LLM hypothesisQwen 2.5 Coder reads the description and outputs a structured hypothesis: vulnerability class, endpoint, payload strategy, scaffolder.
3 — ScaffolderMaps ecosystem to the matching Docker Compose lab template.
4 — Docker labBuilds and starts an ephemeral lab with the vulnerable package pinned. Torn down when the run finishes.
5 — Playwright verificationExecutes the PoC, captures screenshots at each HTTP step, records request/response pairs, writes the HTML report.

4. Binary RE Engine

binoracle pwn ./binary           # full exploit chain
binoracle triage ./binary        # mitigations, symbols, imports
binoracle decompile ./binary     # multi-backend decompilation
binoracle rop ./binary           # ROP gadget search + chain
binoracle hardening ./binary     # hardening assessment

binoracle mcp-server

6. Reports

Each CVE investigation produces a structured HTML report containing: executive summary with CVSS score, LLM hypothesis with reasoning chain, lab scaffold configuration, Playwright screenshots at each step, complete PoC code, and remediation recommendations.
